# 地址、报文与出口策略

## 示例地址

| 设备 | IP / 作用 | 应避免的错误 |
|---|---|---|
| 5G 路由器 LAN | 192.168.66.1/24 | 只写目标 IP，没有正确掩码/下一跳 |
| 机器人 eth0 | 固定 192.168.66.10/24 | DHCP 与固定地址冲突 |
| 机器人 eth1 | 固定 192.168.10.200/24 | 从底盘 LAN 接受默认路由 |
| 底盘路由器 LAN | 192.168.10.1（现场也可能有别名） | 默认上游仍指向没有互联网的无线 |
| 底盘控制器 | 192.168.10.10/24，网关 .10.1 | 为了跨网段调试随意修改设备网关 |
| 调试设备 | DHCP 192.168.66.x/24，网关 .66.1 | 测试时 HTTP 实际走另一块网卡 |

底盘路由器 DHCP 地址池需排除 `.10.200`；ARP 无响应只能说明探测时未发现冲突，休眠设备可能暂时不回应，仍需核对地址规划。

## 三条路径

**热点调试：** 客户端 `.66.x` → `.66.1` 查静态路由 → 机器人 `.66.10` → eth1 把源变成 `.10.200` → 底盘 `.10.10:9001`。回复由机器人还原 NAT，并对经过路由器的连接沿原路返回。9090 的只读诊断 WebSocket 同样走这条单播路径。

**底盘上网：** `.10.10` → 原网关 `.10.1` → 路由器新默认上游 `.10.200` → 机器人选主用 IPv4 出口 → MASQUERADE → 办公 WiFi 或 5G → 互联网。底盘 IP、网关、DNS 保留；底盘路由器仅改上游、DNS、无线开关。

**机器人自己上网：** 本机流量经主路由表，优先 metric 更小的默认路由。健康脚本调整 IPv4 metric；IPv6 是另一套路由，本项目不修改。

## 网络词汇

| 名称 | 可以这样理解 |
|---|---|
| 子网 / 掩码 | 设备认为哪些地址可以在本地直接寻找 |
| 默认网关 | 没有更具体路由时，把报文交给谁 |
| 静态路由 | 给一个特定目的网段安排下一跳 |
| IPv4 转发 | 允许机器人替其他设备转送报文 |
| SNAT / MASQUERADE | 修改源地址，让回复能找到可达的中间节点 |
| 连接跟踪 | 记住一条连接，让回复恢复到原发起者 |
| metric | 同样具体的路由之间比较的优先级，数字越小越优先 |
| DNS | 把域名变成地址；它与 ping、HTTPS 是不同测试层次 |
| 中位数 / P95 | 常见水平 / 较慢的尾部水平；P95 不是最大值 |

## 防止环路与误开放

eth1 设置 `ipv4.never-default yes`、忽略自动 DNS。机器人不会把未知互联网目的地再交回底盘路由器。独立 nftables 表只放行底盘出站、调试 LAN 到底盘，以及对应返回流量；不增加公网入站端口映射。

此方案不桥接两个 LAN，不合并 DHCP 域，不做 ARP 欺骗，也不接管路由器的网关地址。若完全不修改底盘路由器、也不修改底盘设备网关，则普通路由方式无法让仍把请求交给旧网关的设备自动改走机器人；本方案采用底盘路由器的小范围修改。

## 出口状态机

默认每 10 秒启动一次探测；每条网卡独立发 UDP DNS 查询，再以同网卡连接经证书校验的 HTTPS。任一个配置平台有响应即可判定该链路本轮可达。平台根路径 404 仍算网络/TLS 可达，不代表语音业务成功。

- WiFi 主用：wlan0 metric 100，eth0 300。
- 连续 3 轮 WiFi 不可达、5G 可达后：eth0 100，wlan0 600。
- WiFi 连续 6 轮恢复，并且距上次切换至少 120 秒后回切。
- 活跃出口再次连续故障时可紧急越过恢复等待；两边都失败则保持当前选择并标记 degraded，避免来回跳。
- 另一虚拟无线接口（如果存在）设为 900，不当作第三张独立无线网卡。

约 30 秒故障确认是参数对应的量级，实际受探测耗时和定时器调度影响，不能承诺精确 30 秒恢复。首次启动和物理掉线时，内核也可能先删除不可用路由。

这是固定偏好 + 可达性故障切换，不是逐包负载均衡，也不是按即时延迟自动排名。正常语音会话中避免为了小幅延迟差频繁切换。仍需用真实鉴权会话验证首音频时延、连续通话和重连行为。
