# 实测数据怎么读

2026-11-06 的一个约 71 秒主采样窗口：确认蜂窝调制解调器处于 NR SA、n78，再与办公 5 GHz WiFi 做 IPv4 配对测试。两路访问同样的目的 IPv4，curl 显式绑定出口并记录源 IP；DNS 用绑定网卡的 UDP 查询，避免测试绕路。没有运行付费语音接口。

## 同一服务器的 ICMP RTT

每个服务器、每条路径 120 个请求；这两组均 120/120 收到。

| 通义平台采样节点 | 44.45 / 110.05 | 35.20 / 41.12 |
| 豆包平台采样节点 | 23.90 / 85.41 | 17.15 / 21.82 |

## 新建 TLS 连接就绪时间

每平台每路径两个节点、两轮、每轮每节点 15 次，共 60 次。根路径响应为 HTTP 404，均验证 TLS 建连与 HTTP 响应；不把它写成 60 次真实语音调用成功。

| 目的 | 5G 中位数 / P95（ms） | WiFi 中位数 / P95（ms） |
|---|---:|---:|
| 通义平台 | 164.79 / 234.49 | 134.99 / 172.46 |
| 豆包平台 | 113.88 / 179.44 | 92.21 / 110.19 |

本窗口 WiFi 的常见时延和尾部波动更好，所以最终采用 WiFi 主用、5G 备用。这是当前场景的选择依据，换地点、运营商、AP 负载或平台节点后需重新测量。

## 避免四个误判

1. 5G 路径 ping 某个公共 DNS 地址不回应，但它的 UDP DNS 查询和其他目标连接正常；不能写成整个 5G 出口 100% 丢包。
2. 蜂窝物联网卡有域名/IP 白名单，某一平台失败可能是准入限制。`*.aliyuncs.com` 并不自动覆盖豆包使用的其他域名；HTTP 入口成功也不保证全部媒体、鉴权、重定向、CDN 地址都已放行。
3. IPv6 原本主要走机器人办公 WiFi。5G WAN 有 IPv6，不等于路由器已经向 LAN 分配可用 IPv6 前缀；这次不改 IPv6，不拿 IPv6 和 IPv4 混成一组比较。
4. 新 TLS 连接耗时不等于完整语音首包时延。实际语音还包括采集、编码、上行、ASR、模型、TTS、播放与重连。

## 还需要哪些测试

真实语音会话 30–60 分钟、忙时与闲时重复采样、真实上游断网后的应用重连、完整业务域名及重定向链、整机断电重启、特殊客户端隔离/VPN 情况。本次未做这些验证，未测带宽聚合和吞吐上限，也没有足够同条件旧 4G 数据来计算“升级 5G 快了百分之多少”。
